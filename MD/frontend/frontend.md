## 화면 규칙

**이모지를 화면에 쓰지 않습니다. 아이콘은 `lucide-react` 한 세트로 통일합니다** (2026-08-25). 이모지는 기기·브라우저마다 모양과 크기가 달라 **같은 줄 글자와 높이가 안 맞고**, 선 아이콘과 섞이면 정리가 안 된 인상을 줍니다. 로고·카테고리 태그·위치·날씨에 있던 것을 전부 걷어냈으니 **다시 넣지 마세요.**

**아래 넷은 「AI로 만든 티」로 분류되는 형태라 쓰지 않습니다** (2026-08-25).
① 제목 위 알약 라벨(chip eyebrow) — 배경을 빼고 글자만 ② 대문자를 벌려 쓴 영문 소제목(`uppercase tracking-[0.1em]`) — 한글 소제목에 자간 정상 ③ 카드 라운드 16px 초과(알약형 태그·버튼은 예외) ④ 1px 테두리와 넓은 그림자를 한 요소에 동시 사용 — 둘 중 하나만.
**본문 대비는 4.5:1 이상**입니다. `--muted-foreground`가 예전 값(45%)에서 4.54:1로 기준에 겨우 걸쳐 있어 40%로 낮췄습니다 — 이런 건 화면이 깨지지 않고 「좀 흐린데」로만 보여서 눈으로는 못 잡습니다.

**프로그램 대표 이미지는 `imageUrls[0]`.** 대표를 고르는 별도 필드는 두지 않습니다. 홈 카드에 자동 슬라이드를 넣지 않습니다(첫 화면 로딩 부담).

**목록에 사진을 넣을 때는 반드시 `cardImageUrl()`을 쓰세요** (2026-09-03, 스키마 20-6). `imageUrls[0]`을 직접 쓰면 **상세용 큰 사진(긴 변 1600px)이 목록 카드에 그대로 내려갑니다** — 카드가 화면에서 260~280px인 자리라 카드 20장이면 한 화면에 5MB가 나가고, **그 사실은 화면 어디에도 안 나타나고 요금 청구로만 드러납니다.** `cardImageUrl()`은 작은 판(600px)을 고르고, 없으면 큰 사진으로 되돌아갑니다.

> **적용되는 자리** — 검색 목록 카드 · 홈 인기 프로그램 · 지도 핀 카드 · 관리자 심사 사진 줄 · 수정 화면의 사진 미리보기. **상세 페이지의 큰 사진은 원본 그대로 둡니다**(사진이 주인공인 화면입니다). 관리자 심사 줄은 **늘어놓는 것만 작은 판이고 누르면 원본이 열립니다** — 심사는 크게 봐야 합니다.

**화면 폭** — 프로그램 상세와 `/provider/apply`는 1440px, 나머지는 1152px입니다. 큰 사진과 큰 글자가 설득의 수단이라 좁히면 구성이 성립하지 않습니다 — 통일하려고 줄이지 마세요.

## 화면 코드를 고치면 `npm run lint`를 반드시 돌리세요 (2026-08-25 신설)

이 프로젝트에는 프론트엔드 테스트 하네스가 없어서, **화면 코드를 지켜주는 자동 검사는 `npm run lint` 하나뿐입니다.** 그런데 `npm test`는 보안규칙과 Cloud Functions만 돌리므로 이 검사가 포함되지 않습니다.

**타입 검사(`tsc`)와 빌드(`vite build`)로는 못 잡습니다.** 대표적인 것이 훅 순서 오류입니다 — 조기 `return` 아래에 `useState`·`useEffect`를 두면 문법은 완전히 정상이고 빌드도 통과하는데, **실행하면 화면이 통째로 비어 버립니다.** 실제로 2026-08-25에 상세 페이지가 이 문제로 안 떴고, 타입 검사와 빌드는 둘 다 통과한 상태였습니다.

`.oxlintrc.json`에 `react/rules-of-hooks: error`가 이미 켜져 있어 **돌리기만 하면 정확히 잡습니다.** 도구가 없어서가 아니라 안 돌려서 놓친 사고였습니다.

> **경고(`warning`)는 지금도 6건 남아 있습니다** — `only-export-components`(Fast Refresh 관련)이고 동작에는 문제가 없습니다. **`error`가 0인지만 보면 됩니다.**
